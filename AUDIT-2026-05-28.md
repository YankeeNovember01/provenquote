## Critical Bugs

### 1. "Unlock Lead" Button Has No onClick Handler — BROKEN
**File:** `app/(dashboard)/dashboard/leads/page.tsx` line 261  
The "Unlock Lead — $85" button for locked leads has no onClick at all. It's dead. A real user who hasn't leased a market sees it and can't click it to pay.  
**Fix:** Wire it to `fetch('/api/stripe/create-checkout', { type: 'lead', leadId, leadPrice })` the same way Markets does.

### 2. Lead Status Changes Are NOT Persisted
**File:** `app/(dashboard)/dashboard/leads/page.tsx`  
The status dropdown (New / Contacted / Won / Lost) updates local React state only. Refreshing the page resets everything.  
**Fix:** On select change, call `supabase.from('pq_leads').update({ status: lowercase(value) }).eq('id', lead.id)`.

### 3. Lead Notes Are NOT Persisted
**File:** `app/(dashboard)/dashboard/leads/page.tsx`  
The "Your notes" textarea is local state only. Notes vanish on refresh.  
**Fix:** Need either a `notes` column on `pq_leads` or a separate `pq_lead_notes` table; upsert on textarea change (debounced).

### 4. Lease Cancellation Button Does Nothing
**File:** `app/(dashboard)/dashboard/leases/page.tsx` line 97–100  
"Yes, cancel" calls `setCancelling(null)` — identical to "Never mind". There's no API call to cancel the Stripe subscription.  
**Fix:** Call an API route that calls `stripe.subscriptions.cancel(subscriptionId)` and updates `pq_market_leases.status = 'expired'`.

### 5. Stripe Lease Success Callback Not Handled
**File:** `app/(dashboard)/dashboard/leases/page.tsx`  
Stripe redirects to `/dashboard/leases?success=1&niche=...&city=...&state=...&price=...` after a successful checkout, but the leases page never reads `searchParams`. The user lands on a page showing hardcoded fake data with no confirmation banner.  
**Fix:** Read `searchParams.success` and show a success toast/banner.

### 6. `/affiliates` Route Is Dead
**File:** `app/(dashboard)/dashboard/billing/page.tsx` line 74  
"View affiliate portal" links to `/affiliates` — that page doesn't exist. Clicking it gets a 404.

### 7. Proposals "Send Response" Is Fake
**File:** `app/(dashboard)/dashboard/proposals/page.tsx`  
`sendResponse()` does a `setTimeout(() => ..., 800)` and updates local state. Nothing is saved to DB, nothing is actually sent. The proposals themselves are hardcoded — no real homeowner submissions.
